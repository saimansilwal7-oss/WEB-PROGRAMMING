# Week 10.1 — E2: Branching and Merging Evidence

## Goal
Practise Git feature branching and integrate an isolated change into the main branch through a GitHub pull request.

## Feature branch
`feature/week10-git-workflow`

## Change made
Added a focused evidence document on the feature branch rather than directly on `main`. This kept the change isolated until it was reviewed and merged.

## Workflow
1. Create a feature branch from `main`.
2. Add a focused change on the feature branch.
3. Open a pull request targeting `main`.
4. Review the changed file and merge the pull request.
5. Verify that the merge is recorded in the repository history.

## Verification
The [merged Portfolio Pull Request #1](https://github.com/saimansilwal7-oss/portfolio/pull/1) documents the branch and merge workflow. The [E2 evidence document](https://github.com/saimansilwal7-oss/portfolio/blob/main/week10-git-workflow-evidence.md) is available on `main` after the merge.

## Learning reflection
A feature branch protects the stable main branch while work is in progress. A pull request provides a reviewable comparison of the proposed changes, and merging integrates the branch history into the main line of development.
