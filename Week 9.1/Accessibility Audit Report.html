Initial accessibility problems

The initial Lighthouse screenshot showed three accessibility audit failures:

1. Buttons do not have an accessible name

Buttons need a meaningful accessible name so people using screen readers can understand their purpose.

2. Insufficient color contrast

Text and its background need sufficient contrast to remain readable for people with low vision or color-vision differences.

3. Heading elements are not in sequential order

Headings should follow a logical hierarchy so assistive-technology users can understand and navigate the page structure.

Accessibility improvements

1. Accessible button names

Use meaningful visible button text whenever possible. Icon-only buttons should have a clear accessible name, such as an appropriate aria-label.

2. Color contrast

Choose readable foreground and background color combinations and verify them with an accessibility checker.

3. Heading hierarchy

Organize headings in a logical order, starting with one page-level heading and using the next heading levels for nested sections.

4. Keyboard skip link

Add a skip link that becomes visible on keyboard focus and moves users directly to the main content.

Conclusion

The saved Lighthouse results show an improvement from 81/100 to 100/100. This activity demonstrates why accessible button names, readable color contrast, and a logical heading structure matter when building websites. A perfect automated score does not guarantee that every part of a site is accessible, so manual testing remains important.
